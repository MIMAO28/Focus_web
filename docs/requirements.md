> 阶段：P04 选题与需求分析

> 状态：需求已定稿，待进入 P05 编码

## 1. 项目概述

**产品名称**：逐句精听（EchoLine）
**形态**：本机运行的单人 Web 应用（浏览器访问 `http://127.0.0.1:8000`）
**一句话**：把自己的听力音频和原文导入，应用自动分句并对齐时间轴，逐句循环听写、自动批改并给出错因反馈。

**面向用户**：本人（个人备考听力，单用户、单机）。
**解决的问题**：
1. 现成网页精听工具只能用平台自带材料，不能导入自己的音频与文本；
2. 手动给音频断句、对时间轴很费时；
3. 听写结果没人批改，错词、漏词、听错的原因无法定位；
4. 练习中断后进度丢失，下次要重新找位置。

**范围边界**：不做账号体系、不做多用户、不做云端部署、不做移动端适配；音频与数据只留在本机。

## 2. 使用场景

| 场景 | 过程 |
|---|---|
| 导入素材 | 选一段 3–10 分钟的音频（mp3/wav/m4a），粘贴原文 → 30 秒内得到逐句列表与时间轴 |
| 逐句精听 | 听一句、写一句；听不清就重复 3 次或降到 0.75 倍速；随时切上/下句 |
| 对照检查 | 提交后看到漏词、多词、错词高亮，以及 DeepSeek 给出的错因与建议 |
| 续练 | 第二天打开应用，上次练到第几句、每句写了什么都在 |

## 5. 技术方案

**总体**：FastAPI 提供本地 HTTP 服务与接口，原生 HTML/CSS/JS 做界面（无构建步骤），SQLite 存数据，DeepSeek 做分句与反馈。

| 层 | 选型 | 理由 |
|---|---|---|
| 后端 | Python 3.14 + FastAPI + uvicorn | 本机已有 Python；接口简单；易于课程演示 |
| 前端 | 原生 HTML/CSS/JS 单页 | 免 Node 构建，`python` 一条命令即可跑；播放器直接用 `<audio>` + `playbackRate` |
| 音频分析 | 浏览器 Web Audio API（decodeAudioData + RMS 包络 + 静音阈值） | 本机未安装 ffmpeg，浏览器解码可覆盖 mp3/wav/m4a，零额外安装 |
| 分句 | DeepSeek `deepseek-chat` + 本地标点兜底 | 断句质量好；无 Key 时仍可运行 |
| 批改 | 本地词级 diff（Levenshtein 对齐）+ DeepSeek 归因 | 结构化结果可靠，AI 只负责解释，避免“AI 说错就对不了” |
| 存储 | SQLite（标准库 sqlite3）+ `data/audio/` | 单用户足够；便于备份与演示 |
| 配置 | `.env`（`DEEPSEEK_API_KEY`、`DEEPSEEK_BASE_URL`、`DEEPSEEK_MODEL`） | 密钥不入库；提供 `.env.example` |

**目录结构（计划）**

```
app/
  main.py            FastAPI 入口与路由
  db.py              SQLite 初始化与查询
  services/
    segmenter.py     分句（DeepSeek + 兜底）
    grader.py        词级 diff 与评分
    ai.py            DeepSeek 调用封装（超时、重试、脱敏日志）
  static/
    index.html  app.js  styles.css
data/                音频与 app.db（gitignore）
docs/                requirements.md  dev-log.md  ai-usage-log.md
.env.example
```

## 7. DeepSeek 使用点与证据

1. **分句**：把整段原文切成适合逐句精听的句子，返回 JSON；不改变原文措辞。
2. **错因反馈**：结合原文与用户听写，指出连读/弱读/同音词等可能原因，给 1–3 条可执行建议。
3. **复习建议**：按错词类型汇总本周薄弱点。

**证据**：`docs/ai-usage-log.md` 记录脱敏后的请求摘要与响应（模型名、耗时、token、结果要点）；界面截图；Key 只出现在本机 `.env`，日志与截图中隐藏。
**配置**：`DEEPSEEK_BASE_URL=https://api.deepseek.com`，`DEEPSEEK_MODEL=deepseek-chat`。

## 9. 风险与对策

| 风险 | 对策 |
|---|---|
| 静音切分不准（连续语流） | 提供每句起止手动微调；“重复 3 次”按句重复，不依赖切分精度 |
| 长音频在浏览器解码占内存 | 限制 30MB；超限给出提示，建议先裁剪 |
| DeepSeek 超时/额度不足 | 本地标点分句 + 本地 diff 兜底，界面提示“AI 暂不可用” |
| 未安装 ffmpeg | 不依赖 ffmpeg，音频分析放在浏览器端 |
| Python 3.14 个别库不兼容 | 只用标准库 sqlite3/urllib + 已安装的 httpx/requests，不引入重型依赖 |
| 密钥泄漏 | `.env` 入 gitignore；日志脱敏；提交前用 `git grep -i sk-` 自检 |
